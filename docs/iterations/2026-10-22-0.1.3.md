# 0.1.3：共享活动停止保护与额度续工查证

本轮修复一个确定缺陷：自建exclusive会话后来被外部客户端使用，stop仍按初始用途取消整个session。3个最小反例均先观察到误发cancel，再实施保守门。外部rpc、未知真实输入和外部/未知队列会持久置sharedStopRequired；只移除owned队列，不调用cancel，不因暂时空闲恢复独占。原生context与真实输入分开；停止和派发屏障保留。

## 结果与范围

- 本地最终全套142通过，0失败/跳过，84.162秒。
- 独立原生客户端专项18检查/4mock通过：HOLD保留、外部BUILD产生真实文件、owned队列移除、恢复不重投、禁止新派发、另一会话继续。
- 原有专属write/edit/HOLD原生链路因取消前检查变化而重验，50检查/8mock通过，第三轮ABORTED且断流。原生构建审批bypass继续标PARTIAL；未重复无改动的历史审批源码fixture。
- 两组自有Job0、端口释放、无外连拒绝/日志溢出，6份选定原生构建及实际Node可执行文件未变。独立审阅先核代码，再只读核验运行证据，不重放套件。

原生API没有request/turn级原子条件取消。当前门保护已观察的共享活动，不能消除检查后其他客户端新进入的竞态；浏览器视觉并发与未知提交故障注入也未在此专项证明。C07只部分关闭，长期清单仍在[validation](../validation.md#known-issues)。

## 原生DSH协作与费用

本轮新获用户授权后，在指定已有工作区新建DSH会话做只读核查，绑定版本化合同且保持原生profile、上下文与输出参数。一次逻辑send对应41次模型采样、78次原生工具调用，原生turn/end=completed与完整答复已存证。合同根未变，没有不明重投，没有创建schedule或修改已有业务会话。

用量导出完整无缺失/冲突：非缓存输入122,507、缓存读14,517,248、缓存写0、输出32,743。最高单次采样的原生上报总输入409,838、输出2,990；这不证明官方满窗/最大输出，不构成双方费用比较。DSH答复中的“未调用付费模型”不能据此记为零费用：被调用的DSH本身确实产生上述模型采样，账单金额未核。

真实Host从tsx源码入口运行，隔离原生测试走构建入口。两者明确分列，未借源码结论覆盖所有构建。DSH指出schedule可向同session followup，Host内timer负责唤醒，创建需原生agent工具；主控复核关键源码。历史重启实验仍是部分观察，不升级为当前干净验收。

## 额度中断结论

[续工手册](../manuals/quota-continuity.md)给出官方credits、原生SDK/exec、Temporal与LangGraph的证据以及社区自动恢复插件限制。推荐保留现有Harness：同一Codex续工优先使用官方可用credits；不追加时，未来可由独立持久化队列推动DSH执行已批准阶段，范围变化与独立验收等待Codex恢复。

自动接管服务未在本轮实现或部署，没有变更Codex计费、注册系统计划任务或创建原生循环提醒。成熟组件不等于本项目已有经过生产验证的双端自动接管成品。

受测指纹与机器摘要见[结果](2026-10-22-0.1.3-results.json)。历史失败和原始私有记录保留，本轮不重跑旧的一次性费用探针。
