# 减少重复读取与等待输出

适用于当前0.1.3及其Skill调用流程。这里复用既有CLI，不增加后台调度、模型代理、截断或原生能力限制。

## 常规等待

首次发送工程任务：

```sh
codex-dsh send --task demo --contract-sha CONTRACT_SHA256 --text-file PROMPT_FILE --allow-model --wait 60 --view summary --request latest
```

保存返回的task/session、contractSha、cursor、generation及最新requestId。非终态且只是观察超时，继续：

```sh
codex-dsh follow --task demo --wait 60 --view summary --request latest --since-cursor SAVED_CURSOR --since-generation SAVED_GENERATION
```

cursor须是返回的有效整数；没有可靠cursor/generation时先省略对应参数取得新摘要，不猜值。每次用新返回值更新。一个窗口未结束不再开status/follow：命令仍在运行时只续读同一进程，等待时间尽量覆盖窗口剩余部分，不用秒级空轮询。60秒是观察窗口，不是原生任务截止时间。

需要实时审批时用listen取代常规follow，保持同task一个watcher，通过另一CLI查询/决定。listen输出JSONL，退出的leaseOpen=false表示该租期已关闭；重开有效窗口，不延用旧审批。不为省输出关掉审批观察。

每次仍检查state、blocked、approvals及新诊断。changed=false只表示当前投影未变，不表示闲置、已完成或已停净；cursor/generation变化也不自动要求重读所有材料。审批、错误、停止变化立即处理；普通步骤前进只保留摘要。

## 材料与结果只展开需要的部分

| 材料 | 复用条件 | 必须重新读取或核验的情况 |
| --- | --- | --- |
| 手册、配置定位、合同正文、已审代码 | 本会话仍有内容，路径/内容hash/用途相同 | 版本、内容、要求或用途变化；压缩后内容缺失；实际连接失败或身份歧义 |
| 原生答复 | 相同requestId及非空resultSha256，全文已读且仍在上下文 | 新请求、同路径hash变化；恢复后全文缺失；需要排错或用户指定中间结果 |
| 测试回执 | 工具核验当前合同、源与运行依赖指纹仍有效 | 源、测试、索引、运行依赖或原始证据变化；检查发现缺口或新反例 |
| 环境/型号证据、非行动警告 | 同一受测运行/文件指纹，事实仍适用 | 安装/运行入口/版本变化、新进程；警告升级或新错误 |

缓存是复用已审内容，不是把文件mtime当作内容证明，也不是省略工具自身的实时目录、身份、权限、合同和停止检查。哈希/有效性判断在本地进行，只返回必要摘要，不每轮打印整份hash清单。合同bind结果足够时直接进入send，不紧接着重复inspect和展开baseline。

RUNNING中的resultFile可能继续写入，不因每次cursor变化全文重读。匹配请求到终态且有resultFile时，按requestId/resultSha256完整读取新答复一次，再检查实际diff、文件和测试；FAILED/ABORTED等也要核对副作用。中间结果、审批和诊断按需要定向读取。材料很长时先搜索/定位相关段落，完整原文和日志仍保存，不用截断后的片段冒充已验收全文。

usage默认在阶段完成、交接或用户询问时取一次，不每个观察窗口取；usage缺失、冲突和实际账单不明仍如实披露。阶段汇报说明新行为、验收结论、下一步或阻塞，不重复粘贴旧合同、答复或同一警告。原始stderr保留，新错误不屏蔽，不全局关闭Git警告来制造安静。

## 主控操作与模型往返

Codex把互不依赖的检索/检查放进一次工具编排，把条件和顺序已确定的机械命令交给本地脚本；每步检查退出状态，失败即停，回传必要结果后再判断。需要审批、范围决定、异常定位或成果验收时回到主控。保留原始日志和子步骤结果，不用一个总退出码掩盖部分失败。

首次先搜索定位，再定向读取；复用已读内容及有效回执。审阅后集中执行一次最终静态/打包检查，仅因新变化或失败重验相应部分。运行中的命令保存sessionId并续读，不再启动同等命令。短小依赖任务由主控直接处理，只有独立定位或专门审阅有价值时才委派。

例如，4项独立检查原本逐项返回模型安排下一项，合并后可以是1次模型可见工具往返，往返次数减少75%；底层仍执行4项检查。这是有前提的流程算例，尚无本次真实任务的往返降幅或客户端内部模型请求计数。上一节文字token减少比例也不能当成调用次数减少比例。

## 保留质量检查

- 代码或运行依赖变化，按影响重新核验回执并运行必要测试；相同有效指纹复用，不要求独立验收者复制未变全套。
- 断线/身份不明时恢复原task/session并核实际副作用，未知接收不重投。停止先调用stop，核stopAttempt/stopDiagnostic与原生终态；重复STOP_PENDING可能有安全价值，不当噪声删除。
- 不跳过审批、保护文件检查、完整新答复、实际diff和最终验收。原生COMPLETED不是成果验收；模型的“通过”也不是测试证据。

## 如何量化

开发者在工具仓库根运行`python -X utf8 -B benchmarks/context_efficiency.py`。这是本地固定样本对照，比较多轮状态全文与latest摘要、无变化摘要与generation增量、未变手册重复展开与hash复用；不启动Host或模型。脚本同时断言审批、错误、停止和答复变更仍能被摘要识别。

参考token数使用明确命名的tiktoken编码，并只统计可见输出文本；不含工具输入、模型历史重放、内部推理或提供方账单。缺少tiktoken时仍提供字符/UTF-8字节统计，不按字符硬换算token。

2026-10-24本机运行结果（tiktoken 0.12.0 / o200k_base，Node 25.5.0 / Python 3.12.9）：

| 固定样例 | 重复模式参考token | 复用模式参考token | 减少量 | 减少比例 |
| --- | ---: | ---: | ---: | ---: |
| 7个请求的状态：全文与latest摘要 | 318 | 168 | 150 | 47.17% |
| 10次相同观察窗口：完整摘要与generation增量 | 1,680 | 996 | 684 | 40.71% |
| 当前合同手册4次相同全文与1次全文+3次hash引用 | 10,924 | 2,902 | 8,022 | 73.43% |

前两项测的是既有控制器能力按推荐方式使用的收益，第三项测稳定材料复用的潜力；如果原流程已经使用这些方式，不能把同一收益再计算一次。三个样例独立，没有换算成某个真实任务的合计节省。8项离线断言覆盖未变仍RUNNING、同cursor审批新增/移除、错误、STOP_PENDING及取消ack、合同变化、新终态答复、同路径新答复hash；这是指定信号保留检查，不是完整协作质量等价证明。

本次数值对应fixture SHA256 `883ed5d51ba35d1694c67d905dc229c8220c6f1066af141eb884e2ddd7757fdd`、手册输入内容SHA256 `1fb858bfd4698cdb60cebe12b32aab4c087f80c1e82aa5a3372aa7578f2f72d0`（UTF-8文本统一LF）。源材料或tokenizer变化后须重新测量，不沿用该数字。

规则也有阅读成本：首轮流程优化（88f37f5）增加271个参考token，随后补充了主控批量执行规则，当前开销以实际文件计数为准。短任务或已经充分复用材料的任务不一定净省；本轮审计、改文档和验证自身的开销也未计入表内，不能把三个样例的减少量当净收益。

用户审计只提供命令次数、字符数和hash，没有wait/view等命令参数，也没有双方计费token；不能据此认定历史轮询全无效，不能把类别重叠数字相加。固定样本减少量不是该历史会话的实省token，更不是双方总费用降幅。真实收益与质量改进仍需下一次获授权工程任务的同条件对照，不能为比较重跑已暂停项目。
