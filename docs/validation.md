## 为何当前安装仍为 PARTIAL

受测安装的 user-approval 构建包含自动许可改装，sandbox 构建包也绕过升级拒绝。因此当前安装不会按源码原有方式询问，不能从“没有事件”判定控制器完整审批通过。控制器保留这个原生行为，没有修改外部安装来制造通过结果。

SOURCE_FIXTURE 在独立测试进程里，仅将这两个包从安装内已有 TypeScript 源码编译并加载；保留原生模块解析，其余 Host 使用原构建。原始源码与编译 fixture 的 12 份文件哈希列在结果中。它实际证明 CLI 可经原生 waterfall 处理允许/拒绝，**不等于当前改装安装已经恢复审批**。普通产品运行不使用此加载器。

独立审阅复现并推动修复了发送/停止并发、Host 别名重复绑定、旧观察覆盖完成状态；对应回归在本地测试中。原生 UI 的 HTTP 200 只证明服务保留，不是浏览器视觉和所有交互 E2E。

## 复现

```powershell
npm ci
npm test
npm run check
$env:DSH_ROOT = 'C:\path\to\deepseek-harness'
npm run test:native
# 可选：明确单独验证原生源码审批，不等同于当前安装
$env:DSH_APPROVAL_SOURCE_FIXTURE = '1'
npm run test:native
Remove-Item Env:DSH_APPROVAL_SOURCE_FIXTURE
```

需要 Windows、Node ≥22.19、Python 3、已构建原生 DSH；源码 fixture 还需要该安装已有 TypeScript。未设置 DSH_ROOT 时原生测试跳过，跳过不能当作通过。测试创建独立 home/cwd，使用合成密钥与模拟 SSE，不装依赖到外部 DSH、不使用真实密钥。测试私有明细保存在 .cache，勿上传。

- 新产品真实 DeepSeek 推理质量，以及双方 token、缓存和费用是否持平或节省。
- 任意子 Agent、后台 job、提醒与所有共享活动的全局无损停止。
- Codex 关闭或额度耗尽后的持续自主主控、跨状态目录全局锁、项目改动事务合入。

历史曾有有限真实 write/edit 验证，但不是本产品当前版本的真实验收，不据此宣称以上项目通过。可以使用当前薄控制层进行授权协作；它保留原生执行入口与配置，并对观察不到的状态明确报告不确定性。
